# SMSForwarder · 短信转发器

当前版本 **v3.0.2**（versionCode 302）。版本更新与安装包见 [Releases](https://github.com/468336329Zc/smsforwarder/releases)。

把手机收到的短信，实时推送到量子密信群机器人。全程在本机运行：机器人配置、关键词规则、转发事件、统计记录与运行日志都只保存在手机本地，不经过任何第三方服务器。

## 核心能力

### 1. 三通道防漏监听

单靠一种监听方式会漏短信：国产 ROM 常拦后台广播，系统「验证码安全保护」甚至会完全不发广播。本应用同时开三条通道，任一条命中即转发，并在日志里标注该条短信来自哪个通道。

| 通道 | 实现 | 触发时机 | 覆盖的漏转场景 |
|---|---|---|---|
| 系统短信广播 | `SmsReceiver`，静态 + 动态双注册，`priority=2147483647` | 收到 `SMS_RECEIVED` / `SMS_DELIVER` 立即触发 | 常规短信；同一发件人的多段长短信按 PDU 自动聚合拼接 |
| 通知栏监听 | `SmsNotificationService` | 短信应用与 `com.miui.securitycenter` 等系统组件发出通知时 | 广播被拦、ROM 限制后台广播 |
| 短信库监听 | `SmsContentObserver` + 4 秒本地兜底轮询 | `content://sms` 出现新记录时 | 系统彻底屏蔽广播、通知也被折叠的情况 |

三条通道都不做「前置词库」放行判断——早期实现会按固定词表决定通知要不要处理，验证码类短信常在词表外被静默丢弃。跨通道重复由转发服务统一去重。

### 2. 关键词规则：条件组 AND / OR + 排除词

单个机器人可以配置多组关键词，规则分两种模式：

- **条件组（推荐）**：组内关键词必须**同时出现**（AND），多个条件组之间**任一满足**（OR）。例如
  - 条件组 1：`竹云科技` + `验证码`
  - 条件组 2：`4A`
  → 只有「竹云科技…验证码」或含「4A」的短信才转发；只出现「爱营销」不会被单独触发。
- **任一关键词**：任意一个词出现即转发（旧版行为，适合宽松场景）。

两种模式都支持**排除词**：正文命中排除词（如 `退订`、`推广`）直接判定不转发，优先于其他条件。匹配前统一做空白归一与小写化，全角/半角与空格差异不影响命中。

规则以 JSON 存在机器人配置里（`ruleJson`），旧版「逗号分隔关键词」在读取时自动迁移为「任一关键词」规则，升级不需要重新配置。

### 3. 消息推送

`QuantumBotClient` 基于 OkHttp 4.12 + Gson 直连量子密信机器人 Webhook：

- 消息类型：`text`、`image`、`file`、`news`，附件上传限制 30MB
- @ 提醒：支持 `@所有人`，或按手机号 `@指定成员`
- 限流：单机器人 **20 条/分钟**滑动窗口，超出排队而非丢弃
- 传输安全：强制 `https://`，证书走系统信任链，`network_security_config` 禁止明文流量

转发成功的消息才计入统计；测试消息不计入。

### 4. 首页数据统计

- **转发趋势折线图**：按「日 / 周 / 月」切换，分别展示近 14 天、近 8 周（周一起算）、近 6 个月每天的转发条数，并给出与上一周期的环比。
- **关键词 TOP5**：本周期内触发转发次数最多的 5 个关键词及对应次数，带横条对比。
- 统计只存「时间 + 命中关键词」，不存短信正文；本机保留最近 200 天、最多 2 万条记录。

折线图由自绘 `TrendChartView` 实现（网格 + 面积 + 折线 + 圆点 + 首/中/尾日期标签），不依赖任何图表库。

### 5. 事件级运行日志

一条短信从被捕获到推送完成，记录为**一个事件**，而不是散落的单行日志：

- 顶部徽标与左侧色条区分「已转发（绿）」与「未转发（琥珀）」。
- 事件内按顺序列出完整链路：`[通道] 捕获短信` → 号码过滤 → 规则摘要 → 条件组判定结果 → 去重结果 → 各机器人推送结果（HTTP 状态与命中关键词）。
- 每条步骤按结果分色：通过为绿、未通过 / 跳过为琥珀、说明为灰。
- 事件最多保留 100 条，页面同时保留最近 12 行系统运行日志，可一键清空。
- 事件正文与发件人统一经 `SecurityUtils` 掩码（验证码、手机号、身份证号、银行卡号），Webhook 里的 `key` / `token` 也不会明文落盘。

### 6. 本机日志

运行日志写入 `files/logs/runtime.log`，单文件超过 500 行自动裁剪为最近 500 行，供问题排查。

## 配置与使用

1. 在量子密信群里创建机器人，复制其 Webhook 地址
2. 主页 →「机器人管理」→ 右下角 + 新建机器人，填入名称与 Webhook
3. 选择关键词规则模式：
   - 条件组：给每组加词，如 `[竹云科技, 验证码]`、`[4A]`，组内必须同时命中
   - 任一关键词：任一词命中即转发，留空表示全部短信
4. 按需填写排除词（如 `退订, 推广`），命中即不转发
5. 可选设置**监听号码**：只转发指定发件人的短信，支持前缀匹配（填 `1069` 可命中 `106900001234`），留空不限制
6. 开启「权限和设置」里的通知监听、电池优化白名单与自启动
7. 回到主页点「测试转发」，向已启用机器人发一条测试消息，确认群内收到

## 版本升级与数据保留

- **固定签名**：所有版本（debug 与 release）统一用仓库内 `keystore/smsforwarder-release.jks` 签名。
  同一签名 + 同一 `applicationId` 的手机，覆盖安装即为普通升级，机器人配置、关键词规则、统计记录与事件日志都会保留，无需卸载。
- **配置备份**：机器人管理页右上角菜单支持「导出配置到剪贴板」与「从剪贴板导入配置」，
  备份内容是机器人配置 + 统计记录（不含短信正文）的 JSON 文本。换机、重装或跨签名迁移时先导出，装好新包再导入。
- 历史版本（v3.0 / v3.0.1）由 CI 随机生成的 debug 签名打包，签名与当前固定密钥不同，
  从这些版本升级到 v3.0.2 需要卸载一次；此后的版本不再需要。

## 权限与系统要求

- 系统：Android 8.0（API 26）及以上，targetSdk 34
- 短信相关：`RECEIVE_SMS`、`READ_SMS`（Android 13+ 另需 `POST_NOTIFICATIONS`）
- 常驻运行：前台服务 `dataSync`、`RECEIVE_BOOT_COMPLETED` 开机自启、`WAKE_LOCK`
- 特殊授权：通知监听服务（`BIND_NOTIFICATION_LISTENER_SERVICE`）、忽略电池优化、自启动管理
- 已内置跳转入口：小米 `com.miui.securitycenter`、华为、OPPO、vivo 的自启动管理页

## 常见问题

**测试转发能收到，真实短信不转发**
看运行日志里这条短信的事件：是哪个通道捕获的、号码过滤是否放行、规则给的判定原因是什么（例如「命中排除词『退订』」「各组未同时满足」）。

**条件组配了却一直不触发**
确认同一组内的词是否都在同一条短信里出现；组内是 AND，缺一个就不成立。想放宽就拆成多个条件组（组间 OR）。

**小米 / 红米设备收不到**
需要同时确认三处：通知监听权限、应用通知里的「通知类短信」子开关、电池策略设为「无限制」。仅给短信权限不足以保活。

**同一条短信收到两条**
转发服务以完整正文做 10 秒滑动窗口去重，窗口内只会转发一次；事件里会明确写出「10 秒内重复正文，去重跳过」。

**群内 @ 不生效**
需勾选「开启 @提醒功能」；手机号留空时行为是 `@所有人`，填写后改为 `@指定成员`。

**日志显示发送失败**
事件里会记录 HTTP 状态。常见原因是 Webhook 失效、机器人被移出群，或触发 20 条/分钟限流（该情况会在下一窗口补发）。

## 数据与隐私

- 全部配置存于应用私有 `SharedPreferences`，统计与事件记录同样只存本地，应用卸载即清除
- 不申请通讯录、定位、存储等与功能无关的权限
- 唯一网络出口是你自己配置的机器人 Webhook 域名

功能更新记录统一写在仓库 [Releases](https://github.com/468336329Zc/smsforwarder/releases) 页面。
