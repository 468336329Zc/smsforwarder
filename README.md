# SMSForwarder · 短信转发器

把手机收到的短信，实时推送到量子密信群机器人。全程在本机运行，机器人配置、短信游标、去重指纹与运行日志都只保存在手机本地，不经过任何第三方服务器。

## 核心能力

### 1. 三通道防漏监听

单靠一种监听方式会漏短信：国产 ROM 常拦后台广播，系统「验证码安全保护」甚至会完全不发广播。本应用同时开三条通道，任一条命中即转发。

| 通道 | 实现 | 触发时机 | 覆盖的漏转场景 |
|---|---|---|---|
| 系统短信广播 | `SmsReceiver`，静态 + 动态双注册，`priority=2147483647` | 收到 `SMS_RECEIVED` / `SMS_DELIVER` 立即触发 | 常规短信；同一发件人的多段长短信按 PDU 自动聚合拼接 |
| 通知栏监听 | `SmsNotificationService` | 短信应用与 `com.miui.securitycenter` 等系统组件发出通知时 | 广播被拦、ROM 限制后台广播 |
| 短信库监听 | `SmsContentObserver` + 4 秒本地兜底轮询 | `content://sms` 出现新记录时 | 系统彻底屏蔽广播、通知也被折叠的情况 |

三条通道之间不做「前置词库」放行判断——早期实现会按固定词表决定通知要不要处理，验证码类短信常在词表外被静默丢弃。

### 2. 跨通道去重

`MessageDeduplicator` 以**完整短信正文的 SHA-256 指纹**为键，做 10 秒滑动窗口去重，30 秒清理过期记录。同一条短信被三条通道同时抓到，只会转发一次。

去重判定不依赖「6 位数字正则」这类启发式规则：那会把 `106900` 这种发件人号码误判成验证码，导致真实验证码被吞。

### 3. 消息推送

`QuantumBotClient` 基于 OkHttp 4.12 + Gson 直连量子密信机器人 Webhook：

- 消息类型：`text`、`image`、`file`、`news`，附件上传限制 30MB
- @ 提醒：支持 `@所有人`，或按手机号 `@指定成员`
- 限流：单机器人 **20 条/分钟**滑动窗口，超出排队而非丢弃
- 传输安全：强制 `https://`，证书走系统信任链，`network_security_config` 禁止明文流量

### 4. 本机日志与脱敏

运行日志写入 `files/logs/runtime.log`，单文件超过 500 行自动裁剪为最近 500 行。写盘前统一经 `SecurityUtils` 掩码：验证码、手机号、身份证号、银行卡号，以及 Webhook URL 里的 `key` / `token` 参数都不会以明文形态落盘或显示。

## 界面

| 页面 | 内容 |
|---|---|
| **主页** | 服务状态（短信权限、通知监听、机器人总数、已启用数、启用清单）；快捷操作（测试转发、机器人管理、权限和设置、运行日志）；使用提示（配置步骤）；右上角菜单（机器人管理、关于） |
| **机器人管理** | 机器人列表，每项含启停开关、测试发送、更多操作（编辑 / 测试发送 / 删除，删除有二次确认）；空列表有引导；右下角 FAB 添加 |
| **添加 / 编辑机器人** | 基本信息（名称、Webhook 地址）；关键词设置；号码过滤（可选）；状态（启用开关、@ 提醒与指定手机号）。长 Webhook 与多关键词按多行展示，不会被截断 |
| **运行日志** | 自检信息（短信权限、通知监听、电池优化白名单、启用机器人数）+ 时间倒序日志，等宽字体，可一键清空 |

「关于」弹窗显示当前版本名与 versionCode，版本号取自 `BuildConfig`，与 `build.gradle.kts` 保持单一来源。

## 配置与使用

1. 在量子密信群里创建机器人，复制其 Webhook 地址
2. 主页 →「机器人管理」→ 右下角 + 新建机器人，填入名称与 Webhook
3. 设置**转发关键词**：短信正文包含其中任一词才推送；留空表示全部短信都推。多个关键词用中英文逗号或换行分隔
4. 可选设置**监听号码**：只转发指定发件人的短信，支持前缀匹配（填 `1069` 可命中 `106900001234`），留空不限制
5. 开启「权限和设置」里的通知监听、电池优化白名单与自启动
6. 回到主页点「测试转发」，向已启用机器人发一条测试消息，确认群内收到

## 权限与系统要求

- 系统：Android 8.0（API 26）及以上，targetSdk 34
- 短信相关：`RECEIVE_SMS`、`READ_SMS`（Android 13+ 另需 `POST_NOTIFICATIONS`）
- 常驻运行：前台服务 `dataSync`、`RECEIVE_BOOT_COMPLETED` 开机自启、`WAKE_LOCK`
- 特殊授权：通知监听服务（`BIND_NOTIFICATION_LISTENER_SERVICE`）、忽略电池优化、自启动管理
- 已内置跳转入口：小米 `com.miui.securitycenter`、华为、OPPO、vivo 的自启动管理页

## 常见问题

**测试转发能收到，真实短信不转发**
依次检查：转发关键词是否命中正文、监听号码是否把发件人挡在外面、通知监听是否已开启（部分 ROM 关掉后只剩广播通道）、日志里是否有「跳过」记录。

**小米 / 红米设备收不到**
需要同时确认三处：通知监听权限、应用通知里的「通知类短信」子开关、电池策略设为「无限制」。仅给短信权限不足以保活。

**同一条短信收到两条**
先确认去重是否生效：同一正文在 10 秒窗口内只推一次。超过 10 秒才被另一通道抓到的，会被视为新消息。

**群内 @ 不生效**
需勾选「开启 @提醒功能」；手机号留空时行为是 `@所有人`，填写后改为 `@指定成员`。

**日志显示发送失败**
日志会记录 HTTP 状态码。常见原因是 Webhook 失效、机器人被移出群，或触发 20 条/分钟限流（该情况会在下一窗口补发）。

## 数据与隐私

- 全部配置存于应用私有 `SharedPreferences`，日志存于私有目录，应用卸载即清除
- 不申请通讯录、定位、存储等与功能无关的权限
- 唯一网络出口是你自己配置的机器人 Webhook 域名
